# GK6323V100C（ChaoGe Z71A）U 盘救援系统：引导 + 刷写 p18

## 一、结论

进临时系统最省事的一条路是：**U-Boot 完全照原样读块启动，只把内核启动参数里的 `root=` 从 eMMC 的 p18 换成 U 盘**。这样 ATF、dtbo、内核全部沿用原 bootcmd，零改动、零风险。

成败只取决于一件事：**U 盘在你的板子上能不能被认出来**。所以先做第 2 节的验证，通过了再动手。

| 项目 | 值 | 来源 |
| --- | --- | --- |
| U-Boot | 2019.07（2024-07-23） | 串口实测 |
| ATF 分区 | p7，起始 LBA 0x10000，2 MiB | 启动日志 mmc read |
| dtbo 分区 | p10，起始 LBA 0x19000，读窗口 16 KiB | bootcmd |
| boot 分区 | p15，起始 LBA 0x38000，读 0x7800 块（15 MiB） | bootcmd |
| 内核运行地址 | uImage 搬到 `0x02000000` | BL31 打印 Entry point |
| dtb 兜底地址 | `0x03FFC000` | 内核内置兜底逻辑 |
| 根分区 | mmcblk0p18 | 启动参数 blkdevparts |

## 二、动手前先核对三件事

三件事分别决定 U-Boot 认不认盘、内核认不认盘、以及盘本身行不行。

### 2.1 U-Boot 侧有没有 USB 命令

TTL 串口 115200，开机按 `Ctrl+C` 打断 autoboot，进 U-Boot 后敲：

```
printenv bootcmd
printenv bootargs
usb start
usb info
```

- `bootcmd` 里若出现 `setenv bootargs ...`，说明它每次会自己重写启动参数，后面第 4 节就要改 `bootcmd` 而不是改 `bootargs`。
- `bootargs` 先整体抄一份留底（第四节的命令要用到完整串）。
- `usb start` 有输出、`usb info` 能列出你的 U 盘，才说明 U-Boot 这一层认盘。

### 2.2 内核侧 USB 存储与 SCSI 磁盘层是否内建

在板子现存的 Debian 里跑：

```
zcat /proc/config.gz | grep -E "^CONFIG_(SCSI|BLK_DEV_SD|USB_STORAGE|USB_EHCI_HCD|USB_OHCI_HCD|EXT4_FS|MMC_DW|USB)="
```

期望值：

| 符号 | 期望 | 作用 |
| --- | --- | --- |
| CONFIG_SCSI | =y | USB 存储依赖它 |
| CONFIG_BLK_DEV_SD | =y | 让 U 盘变成 /dev/sdX |
| CONFIG_USB_STORAGE | =y | U 盘驱动本体 |
| CONFIG_USB_EHCI_HCD / USB_OHCI_HCD | =y | 两个 USB 控制器 |
| CONFIG_EXT4_FS | =y | 挂载救援盘上的 ext4 根 |
| CONFIG_MMC_DW | =y | 认 eMMC（要写 p18） |

任何一项是 `is not set` 或 `=m`，都要先在 `kernel.config` 里补 `=y` 再重编——`=m` 在救援系统里没有对应模块可加载。

### 2.3 U 盘本身在你的板子上认不认

板子插上 U 盘，看内核反应：

```
sudo dmesg -w
```

另开一个窗口看块设备：

```
lsblk -o NAME,SIZE,TRAN,MODEL
```

- 出现 `sda` 就是通了，可以往下走。
- 若反复刷 `new full-speed USB device number N`、`device descriptor read/64, error -62` 这类枚举失败，按顺序换：**换一个 USB 口 → 换一只老式 USB 2.0 小容量 U 盘 → 加一个有外部供电的 USB HUB**。

> 你之前的日志里，USB 声卡在 OHCI 口（bus 2）就是这个反复枚举失败的样子。U 盘是高速设备，正常应该挂到 EHCI（bus 1）；如果它也被挂进 OHCI，说明该口或供电有问题，先按上面三步排除。

## 三、做一个 Buildroot 救援系统

只需要一个带 `dd`、`gunzip`、`e2fsck`、`blkid` 的最小 aarch64 系统，不编内核（内核用你已经在 p15 上那份）。

在任意 x86_64 Linux 或 WSL2 里：

```sh
sudo apt install -y build-essential git libncurses-dev bison flex \
  libssl-dev bc rsync cpio unzip file wget python3

git clone -b 2025.02.x --depth 1 https://gitlab.com/buildroot.org/buildroot.git
cd buildroot
```

把下面这段存成 `configs/gk6323_rescue_defconfig`：

```
BR2_aarch64=y
BR2_cortex_a55=y
BR2_TOOLCHAIN_BUILDROOT_GLIBC=y
BR2_INIT_BUSYBOX=y
BR2_SYSTEM_BIN_SH_BUSYBOX=y
BR2_TARGET_GENERIC_HOSTNAME="gkrescue"
BR2_TARGET_GENERIC_ISSUE="GK6323 Rescue"
BR2_TARGET_GENERIC_GETTY_PORT="ttyAMA0"
BR2_TARGET_GENERIC_GETTY_BAUDRATE_115200=y
BR2_TARGET_GENERIC_REMOUNT_ROOTFS_RW=y
BR2_ROOTFS_DEVICE_CREATION_DYNAMIC_EUDEV=y
BR2_PACKAGE_BUSYBOX_SHOW_OTHERS=y
BR2_PACKAGE_E2FSPROGS=y
BR2_PACKAGE_UTIL_LINUX=y
BR2_PACKAGE_UTIL_LINUX_BINARIES=y
BR2_PACKAGE_GZIP=y
BR2_PACKAGE_COREUTILS=y
BR2_PACKAGE_KMOD=y
BR2_TARGET_ROOTFS_EXT2=y
BR2_TARGET_ROOTFS_EXT2_4=y
BR2_TARGET_ROOTFS_EXT2_SIZE="256M"
BR2_TARGET_ROOTFS_TAR=y
BR2_TARGET_ROOTFS_CPIO=y
BR2_TARGET_ROOTFS_CPIO_GZIP=y
# BR2_LINUX_KERNEL is not set
```

编译：

```sh
make gk6323_rescue_defconfig
make -j"$(nproc)"
```

产物在 `output/images/`：

| 文件 | 用途 |
| --- | --- |
| rootfs.tar | 解到 U 盘，做救援系统根 |
| rootfs.ext4 | 也可直接整盘 dd 到 U 盘 |
| rootfs.cpio.gz | 第六节网络引导用的 initramfs |

> `BR2_PACKAGE_GZIP=y` 不能省：`flash-partition.sh` 用 `gzip -l` 预读解压后大小，BusyBox 自带的 gzip 不一定支持 `-l`。

## 四、把救援系统摆到 U 盘上

目标布局（整盘一个 ext4，不建分区表）：

| 路径 | 内容 |
| --- | --- |
| `/` | Buildroot 的 rootfs 内容 |
| `/flash/rootfs.img.gz` | 要刷进 p18 的新 rootfs |

在**板子现存的 Debian 上**做（U 盘插板子 USB 口，脚本会先列盘让你核对）：

```sh
sudo sh mk-rescue-usb.sh -l
sudo sh mk-rescue-usb.sh /dev/sda rootfs.tar rootfs.img.gz
```

脚本最后会打印文件系统 UUID，记下来，第 5 节要用。

如果板子上没有这两个产物文件，先用 `scp` 把 GitHub Actions 出的 `rootfs.img.gz` 和 Buildroot 的 `rootfs.tar` 传上去。

> 整盘不建分区表，所以内核里它是 `/dev/sda`（不是 `/dev/sda1`）。用脚本打印的 `root=UUID=...` 最稳，不怕设备名变化。

## 五、U-Boot 里引导进救援系统

TTL 串口打断 autoboot，先确认留底，再改启动参数。下面整段可以直接粘进串口终端（把 UUID 换成上一步打印的值）：

```
printenv bootargs
setenv bootargs 'earlycon=pl011,mmio32,0xf8b00000,115200n8 console=ttyAMA0,115200n8 console=tty0 clk_ignore_unused net.ifnames=0 root=UUID=在这里填你那个UUID rootfstype=ext4 rootwait rw panic=-1 blkdevparts=mmcblk0:1M(fastboot),512K(bootargs),512K(bootargsbak),20M(recovery),2M(deviceinfo),8M(securestore),2M(atf),8M(baseparam),8M(pqparam),2M(dtbo),10M(logo),10M(logobak),20M(fastplay),20M(recoverybak),60M(boot),20M(misc),20M(trustedcore),-(rootfs)'
run bootcmd
```

每行在干什么：

- `root=UUID=...`：把根从那块 eMMC 的 p18 换到 U 盘。读不到 UUID 就退回写 `root=/dev/sda`。
- `rootwait`：等 USB 控制器和 U 盘枚举完成再找根，USB 设备必须带这个。
- `blkdevparts=...`：**必须原样保留**，救援系统里 `/dev/mmcblk0p18` 才存在，否则刷不了。
- `run bootcmd`：走原厂那条 bootcmd，照旧从 p7 读 ATF、p10 读 dtb、p15 读内核，只有根被换掉。

如果第 2.1 步发现 `bootcmd` 里带 `setenv bootargs`，就把这一句改成覆盖 `bootcmd`：

```
setenv bootcmd 'setenv bootargs earlycon=pl011,mmio32,0xf8b00000,115200n8 console=ttyAMA0,115200n8 console=tty0 clk_ignore_unused net.ifnames=0 root=UUID=你的UUID rootfstype=ext4 rootwait rw panic=-1 blkdevparts=mmcblk0:1M(fastboot),512K(bootargs),512K(bootargsbak),20M(recovery),2M(deviceinfo),8M(securestore),2M(atf),8M(baseparam),8M(pqparam),2M(dtbo),10M(logo),10M(logobak),20M(fastplay),20M(recoverybak),60M(boot),20M(misc),20M(trustedcore),-(rootfs); mmc read 0 0x02000000 0x10000 0x1000; mmc read 0 0x03FFC000 0x19000 0x20; mmc read 0 0x04000000 0x38000 0x7800; bootm 0x04000000 - 0x03FFC000'
run bootcmd
```

**不要 `saveenv`**。这些改动只在内存里生效，拔电就恢复原样，你随时能退回正常启动。

## 六、进救援系统后刷 p18

串口上看到 Buildroot 的 shell 后：

```
cat /proc/partitions          # 确认 mmcblk0p18 在
ls -lh /flash
```

刷写：

```
gunzip -c /flash/rootfs.img.gz | dd of=/dev/mmcblk0p18 bs=4M conv=fsync
sync
```

或者用之前那个带校验的脚本（需要把 `flash-partition.sh` 也拷到救援盘上）：

```
sh /flash/flash-partition.sh /flash/rootfs.img.gz -y /dev/mmcblk0p18
```

收尾：

```
poweroff
```

断电 → **拔掉 U 盘** → 上电，就从新 rootfs 启动了。首次开机会由 `resize-once` 把 p18 扩到整分区。

## 七、U 盘认不出来时的备用路径：走网络

如果第 2.3 步验证下来 U 盘始终不认，改走网络。你的内核 `CONFIG_HISI_FEMAC=y`、U-Boot 日志里有 `Net: up`，这条路不依赖 USB。

要点是先让 **PC 和板子在同一网段**（板子在副路由的 192.168.1.x，U-Boot 没有路由，跨网段访问不到）。

PC 上一份 TFTP 根目录，放 `boot.img`、`gk6323v100c-chaoge-z71a.dtb`、`rootfs.cpio.gz`；再起一个 HTTP 服务放 `rootfs.img.gz`。

U-Boot 里：

```
setenv ipaddr 192.168.1.200
setenv serverip 192.168.1.100
ping 192.168.1.100
mmc read 0 0x02000000 0x10000 0x1000
tftp 0x04000000 boot.img
tftp 0x03FFC000 gk6323v100c-chaoge-z71a.dtb
tftp 0x08000000 rootfs.cpio.gz
setenv bootargs 'earlycon=pl011,mmio32,0xf8b00000,115200n8 console=ttyAMA0,115200n8 console=tty0 clk_ignore_unused net.ifnames=0 root=/dev/ram0 rw panic=-1'
bootm 0x04000000 0x08000000:${filesize} 0x03FFC000
```

进系统后同样用 `udhcpc` 拿地址，然后流式刷：

```
udhcpc -i eth0
wget -O - http://192.168.1.100:8000/rootfs.img.gz | gunzip | dd of=/dev/mmcblk0p18 bs=4M conv=fsync
sync
```

> 这条路要求内核带 initramfs 支持（`CONFIG_BLK_DEV_INITRD=y` 与 `CONFIG_RD_GZIP=y`）。第 2.2 步顺手一起查一下。

## 八、常见卡点对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| U-Boot 里 `usb start` 无输出 | U-Boot 未编 USB 命令 | 只能走第七节网络路径 |
| 内核起来后卡在等根 | USB 枚举慢或失败 | 已加 rootwait；换口/换盘/加供电 HUB |
| `VFS: Cannot open root device` | root 值写错 | 用 `blkid` 读出的 UUID，或改 `/dev/sda` |
| 救援系统里找不到 p18 | bootargs 的 blkdevparts 被丢了 | 第五节的命令必须整串保留 |
| 刷完开机还是老系统 | 写了别的分区 | 确认写的是 `/dev/mmcblk0p18` |
